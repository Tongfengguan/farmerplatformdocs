后端设计 (Spring Boot 3) ​

后端系统是 Farmer Platform 的心脏，位于 backend/farmer_platform 目录。它基于 Java 21 和 Spring Boot 3 构建，遵循领域驱动设计 (DDD) 的部分理念，提供稳定、安全、可分页的 RESTful API。

1. 核心技术选型 ​

  • 运行环境: Java 21 LTS
  • 核心框架: Spring Boot 3.2+
  • 持久层: Spring Data JPA / Hibernate
  • 数据库: MySQL 8.x
  • 安全认证: JJWT (Java JWT)
  • 工程提效: Lombok (减少 Getter/Setter 样板代码)

2. 目录架构与分层 (Layered Architecture) ​

代码严格按照标准的三层架构（Controller -> Service -> Repository）进行组织：

  • config: 存放 Spring 的配置类，例如 CORS 跨域配置 (WebConfig.java)。
  • controller: 负责暴露 REST API 路由，接收前端请求并校验基本参数，然后转发给 Service 层。
  • service: 封装所有的核心业务逻辑（如生成订单、计算总价、密码比对）。
  • repository: 继承 JpaRepository，负责与 MySQL 数据库交互，执行 CRUD 和动态查询。
  • entity: JPA 实体类，通过 @Entity 和 @Table 注解直接映射到数据库表。
  • dto (Data Transfer Object): 用于在 Controller 和前端之间传输数据。例如 LoginRequest, ProductResponse。DTO 严格隔离了数据库实体结构与对外暴露的数据结构。
  • common: 存放全局通用的工具类与统一包装对象，如 ApiResponse<T> 和 PagedResponse<T>。
  • security: 存放自定义的 AuthInterceptor 和 JWT 生成/解析工具。

3. 安全架构 (JWT Security) ​

我们没有引入沉重的 Spring Security，而是实现了一个轻量级、高可控的 AuthInterceptor。

3.1 鉴权流程 ​

  1. 用户调用 /api/auth/login 接口，传入账号密码。
  2. AuthService 验证通过后，调用 JwtService 生成一个签名的 Token，并返回给前端。
  3. 前端在后续请求的 HTTP Header 中附带 Authorization: Bearer <token>。
  4. AuthInterceptor 在请求到达具体 Controller 之前进行拦截：
    • 提取 Header 中的 Token。
    • 验证 Token 的签名与有效期。
    • 如果验证失败，抛出 401 未授权异常，由全局异常处理器接管。

3.2 跨域与 OPTIONS 预检 ​

AuthInterceptor 针对浏览器的 CORS 机制进行了专门适配，强制无条件放行 OPTIONS 请求，避免前端的预检请求被误杀为 401。

4. 分页第一原则 (Pagination First) ​

在后端开发中，所有的列表查询接口必须实现分页。这保证了在面对成千上万条农产品或订单数据时，服务器内存与网络带宽不会被撑爆。

实现方式:

  1. Controller 接收前端传来的 page (当前页码，默认 0) 和 size (每页条数，默认 10)。
  2. 构建 PageRequest.of(page, size)。
  3. 调用 Repository 继承的基于 Pageable 的查询方法。
  4. 将查询结果 (包含数据列表、总页数、总条数) 封装为 PagedResponse<T> 并由 ApiResponse 包裹返回。

5. API 统一响应规范 ​

为了让前端能够有一致的处理逻辑，后端抛弃了随意的返回格式，所有的接口必须返回标准的 ApiResponse：

json
{
  "code": 200,          // 业务状态码 (200: 成功, 401: 未授权, 400: 业务异常, 500: 服务器错误)
  "message": "操作成功", // 提示信息
  "data": { ... }       // 具体的业务数据结构
}
